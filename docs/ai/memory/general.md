- **When documenting a filename pattern or any code-generated format, READ THE GENERATOR FIRST.** Don't guess from doc-text, from a sibling doc, or from memory. F-55 sweep: my initial fix to `instruction-builder.md` used `tomo-moc-proposal-<YYYYMMDD>-<HHmm>-<slug>.md` — copied from `moc-architect.md` — when the actual producer (`suggestions-reducer.py:558-561`) was both the source of truth AND the outlier (it produced a format inconsistent with the canonical Tomo `<YYYY-MM-DD>_<HHMM>_<role>.md` shape used by suggestions/instructions/suggestions-fan). The 1-line doc-text fix turned into a 7-commit producer + consumer + doc + test sweep once the generator was actually read. Path: `grep -n 'filename = ' producer.py` → read `strftime` format → that IS the answer. Applies to filenames, frontmatter blocks, JSON payload shapes, anything Tomo emits programmatically. **Bonus principle**: when fixing a documented format, also verify producer + consumer + sibling docs all agree before committing the doc fix in isolation — silent drift between them is the trap.
- **Tomo artifact filename canonical form**: `<YYYY-MM-DD>_<HHMM>_<role>[-<slug>].md`. Examples: `2026-05-22_1407_suggestions.md`, `2026-05-22_1407_instructions.md`, `2026-05-22_1407_suggestions-fan.md`, `2026-05-22_1407_moc-proposal-zsh-shell-tools.md`. Generator: `time.strftime("%Y-%m-%d", ...)` + `time.strftime("%H%M", ...)`. Producers: `suggestions-reducer.py` (moc-proposal mode), `instruction-render.py` (via `upload-rendered.py` L68). Backward-compat: parser + mark-captured filter accept the legacy `tomo-moc-proposal-*` pattern so pre-F-55 vault files don't orphan. F-55 shipped 2026-05-22.

<!-- 2026-05-09 -->
- **Hidden entries in Tomo template sources (`tomo/`, `docker/`, `claude-docker-home/`) MUST use `dot_` prefix, not literal `.X`.** Host sandbox denies `unlink` on literal hidden files/directories inside template dirs during `git checkout`/`merge` — Edit/Write still work, so the failure is invisible until a branch switch. Renderer (`scripts/update-tomo.sh`) maps `dot_X` → `.X` at sync via hardcoded path mappings; today only `dot_claude/` exists, no other hidden template entries are needed. Adding a new hidden template entry = rename source to `dot_<name>` + add a matching `update_managed`/`mkdir -p` block in `update-tomo.sh`. Audited 2026-05-09: zero literal hidden entries in any template source. Source: Kouzou heads-up `_archive/inbox/from-kouzou/2026-05-09_kouzou-to-tomo_dot-prefix-for-hidden-template-files.md` (when archived).

<!-- 2026-05-08 -->
- **Spec/schema contradiction → deviation note pattern.** When a task spec asks for output that violates a downstream schema, document the deviation in the plan file under that task with: (a) the schema constraint that blocks literal compliance, (b) the consumer behaviour that makes the deviation safe, (c) the chosen alternative. Don't quietly comply (downstream breaks); don't push back blindly (spec author had a reason). F-43 T4.3 example: spec said "stub `result.json` with `actions: []`" but `item-result.schema.json:33` declares `actions:{minItems:1}`; pragmatic fix was to skip writing `result.json` entirely and rely on `suggestions-reducer.py:758` "skip gracefully" handling. Recorded as a deviation block in `phase-4.md` under T4.3.
- **Module-level imports execute regardless of textual position — late imports are not bugs.** Pytest collects all module-level statements before invoking any test function; function bodies resolve names at call time. A `from lib import foo` at line 268 (after test functions calling `foo.bar()`) is a code smell, not a NameError. When a code-quality reviewer flags "Critical NameError" on test code that demonstrably passes, **run the tests first** before applying the "fix". Hoist for hygiene if you wish, but don't treat this class of finding as a blocker.
- **Mock shape must match the consumer's actual access pattern, not your intuition.** Augments `feedback_mocks_verify_library_reality.md` (auto-memory): the rule applies even when YOU are authoring the mock for in-house code in this same session. Read the consumer's accessor expression (`note["content"]` vs `note.content` vs `note.get("content")`) before finalising the mock's return shape. F-43 T4.4 e2e: my fake `read_note` returned a class with `.content`; renderer at `instruction-render.py:405` used `note.get("content", "") if isinstance(note, dict)`; tests silently fed empty content and Rule 4.2/4.5 paths emitted wrong action counts.
- **Deferred-pipeline-assembly creates "half-wiring" deviations — surface, don't expand scope.** When a child task assumes a parent pipeline is wired but the parent shipped helpers individually without an orchestrator (`main()` raises NotImplementedError), the child task may correctly ship its half (e.g., load+save) but not the threading. Pattern: document as a deviation in the plan file naming the missing parent task; don't grow the child's scope to fix the parent gap. F-43 T5.1 example: `phase6_dedupe(squelch_registry)` call site doesn't exist because Phase 2 left `main()` un-assembled; T5.1 shipped load/decrement/save and noted the threading deviation under its task entry in `phase-5.md`.

<!-- 2026-05-06 -->
- Before brainstorming a new feature in Tomo, grep `docs/XDD/reference/tier-3/` and `tomo/schemas/` for prior art. F-43 (MOC-creation skill) had ~70% of the spec already in place — `tier-3/lyt-moc/new-moc-proposal.md`, `moc-matching.md`, `t_moc_tomo` template, and the `create_moc` / `add_relationship` actions in `instructions.schema.json` — that a greenfield brainstorm would have duplicated. The pattern: tier-3 = "what should happen", schema = "how the action is shaped"; both often pre-date the user-facing skill that wires them up. Saves ~30% of brainstorm time and avoids accidental contradictions with existing spec.

<!-- 2026-05-07 -->
- Orchestrator slash commands have two valid model interpretations: **impersonation** (parent reads the orchestrator's body and acts on it) vs **dispatch** (parent spawns the orchestrator as a Task subagent). Impersonation costs ~60% more tokens than dispatch on /inbox-shape workflows because the parent re-reads context that a fresh subagent would receive cleanly. Lock the reading explicitly with STRICT/NEVER wording in the orchestrator's frontmatter — and pick dispatch unless the orchestrator must fan out further subagents (nested Agent dispatches fail). Touch point: any new orchestrator agent in `tomo/dot_claude/agents/`. Confirmed 2026-05-01 /inbox token analysis.
- Haiku is **not** strong enough for STRICT-orchestration agents — twice in /inbox runs a haiku-pinned orchestrator silently skipped Pass-2 dispatch and rendered the artefact itself instead of running the deterministic scripts (Step 2.5 fan-resolve and instruction-render were both bypassed). Pin sonnet or opus for orchestration roles; haiku is fine for terminal/leaf subagents that only follow a literal script. Touch point: `model:` field in orchestrator agent frontmatter. Confirmed 2026-05-01 (twice in same session).

- **A feature/flag that spans a DECISION branch AND a DATA-ASSEMBLY step must be tested at BOTH layers — testing only the decision lets a broken assembly pass CI.** `inbox-triage --recover` was half-wired: `determine_action` returned `"suggest"` on `recover and captured_hits`, but `build_routing_plan` built the `fresh_sources[]` dispatch list from `new_sources` only — so recover flipped the action yet handed the conductor an empty list (silent no-op). The only test (`test_recover`) asserted the action and passed while the feature was dead. Found in spec 021 T4.3 live validation 2026-06-09; fixed in `inbox-triage` 0.8.0. Rule: when a flag's effect crosses two functions (decide → assemble → dispatch), write a test that asserts the *downstream artifact* (the dispatch list / emitted payload), not just the branch taken. Sibling of `feedback_count_parity_not_correctness` (validate execution, not output shape).
