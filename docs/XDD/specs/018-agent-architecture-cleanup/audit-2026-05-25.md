# Runtime-Deviation Risk Audit — 2026-05-25

Audit of `tomo/dot_claude/{agents,skills,commands}/` against the
CLAUDE.md rules locked 2026-05-25. `tomo/dot_claude/rules/` is OUT OF
SCOPE — those files are session-level rule context, not runtime agent/
skill/command files.

1. **Runtime files contain only imperatives, tool invocations, branching.**
   Descriptions of called-script behavior, historical context, spec
   references, and dates belong in `docs/tomo/<mirrored-path>.md`.
2. **STRICT blocks with one-line `Why:` are an emergency lever**, used
   only when an unadorned imperative has been observed producing
   runtime deviation.

This audit identifies where the runtime files currently violate either
rule and prioritises cleanup.

## Methodology

| Pattern | Detection | Severity |
|---------|-----------|----------|
| Spec refs (`F-NN`, `XDD-NNN`, `ADR-N`) | `rg 'F-[0-9]+\|XDD[ -][0-9]+\|ADR-[0-9]+'` | High — backlog cross-refs |
| Calendar dates (`YYYY-MM-DD`) outside code examples | `rg '2026-[0-9]{2}-[0-9]{2}'` + manual triage | Medium — most are sample timestamps (OK) |
| Parenthetical citations (`(per X)`, `(see Y)`, `(verified Z)`, `(2026...)`) | `rg '\(per \|\(see \|\(ref \|\(verified \|\(shipped \|\(2026'` | Medium — internal-section `(see ...)` is OK; spec/date parens are violations |
| Historical wording (`legacy`, `previously`, `was added`, `replaced by`, `formerly`) | `rg -i '(legacy\|previously\|originally\|was added\|deprecated\|replaced by\|formerly)'` | High |
| Script-describes-self (`this script`, `the script does/reads/computes/...`) | `rg -i '(this script\|the script (does\|reads\|writes\|...))'` | Critical — direct deviation risk |
| STRICT blocks | `rg '^#+ STRICT\|\*\*STRICT'` | Tracking only — need Why pairing |
| `Why:` lines | `rg '^Why:\|^\*\*Why:'` | Pairing reference |
| Rationale headings (`## Background`, `## History`, `## Notes`, etc.) | `rg '^#+\s+(Background\|History\|Notes\|Why\|Rationale\|Context\|Implementation)'` | High |

## Out of scope for this audit

- **Persona prose in agent files** — "You are X who does Y" type sections that define agent identity are imperative-equivalent and don't qualify as rationale prose. Not flagged.
- **Workflow step descriptions** — "Step 1: Read config. Step 2: Run X." style step bodies are imperative-shaped. The "what the step does" wording flagged elsewhere is when it goes into "the script that this step calls reads X, computes Y" describing the script's internals.
- **Constitutional sections in CLAUDE.md and rules/** — those are designed to be loaded into runtime context as instruction. Different audience (the CLAUDE Code session, not a specific agent's workflow), different rule.
